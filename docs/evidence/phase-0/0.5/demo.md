# Step 0.5 — Demo

## `pnpm db:migrate` builds a clean database
CI starts an empty Postgres 17, runs `pnpm db:migrate`, then lists what it created (`\dn`, `\dt *.*`). The output is in `ci.txt`.

## What the migrations create
| Schema | Owner | Tables |
|---|---|---|
| identity | identity module | `consent_ledger` (append-only) |
| roster, content, assessment, session, gamification, notification, reporting | their modules | none yet |
| outbox | platform (ADR-003) | `events` |
| audit | platform | `log` (append-only) |
| drizzle | migration tool | `__drizzle_migrations` |

- **Migration files:**
  - `services/api/migrations/0000_init.sql` is generated by drizzle-kit from the table definitions;
  - `0001_append_only.sql` is hand-written: the triggers that make two tables append-only.
- **Append-only, as seen by the database:**

  ```
  update audit.log set action = 'x' where id = $1
  ERROR:  audit.log is append-only (UPDATE not allowed)
  ```

## Guarding the rules for future tables
- **Tenant ID on every table:** two tests check it, one on the table definitions (`tables.test.ts`) and one on the live database (`migrations.test.ts`). A new table without a non-null uuid `tenant_id` fails CI.
- **Migrations stay in sync:** `pnpm generate` re-runs `drizzle-kit generate`. CI fails if a table changed without a committed migration.
